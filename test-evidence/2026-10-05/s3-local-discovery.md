# S3 local discovery implementation evidence

5 October 2026, Pacific/Auckland. This is local code and test evidence, not S3 release acceptance or deployment evidence.

The API now reads persisted published Offerings for authenticated paginated search and detail routes, excluding the current member, paused/closed/draft listings, legacy-unknown pricing and non-NZD rows. Search accepts category, availability and a small explicit related-wording vocabulary. Owner-authorised Need matching excludes self, nonpublished, wrong-category, incompatible price basis/currency, known location/time and budget incompatibilities. Responses include actual public Offering details, factor scores, reasons and configured policy version. Matching weights are validated at API startup and applied to calculator scores. The React signed-in discovery, search, detail and match views use these API responses; illustrative preview data stays separate.

Verification on the current working trees after the 5 October audit: 39 backend tests passed, one opt-in SQL acceptance test skipped; 47 frontend tests passed; frontend lint and production build passed; offline dashboard verification passed. The audit corrected three edge cases: an unknown start date no longer satisfies `availableToday`, an offer priced entirely below a Need's minimum is excluded, and a zero-weight factor no longer appears as a positive score explanation. The backend integration test exercises two synthetic authenticated accounts, public detail allowlisting, self exclusion, paused listing removal and enriched matching with EF InMemory. It does not prove SQL translation, real Cognito, a browser journey, AWS staging or representative semantic quality. Rendered Word visual QA was attempted but soffice.exe is unavailable.

Remaining S3 exit evidence: owner-reviewed related-wording and hard-exclusion fixtures, including the intended treatment of prohibited candidates; real SQL Server persistence/query and cross-account/browser checks; staging configuration; and 10,000-offering workload latency. Current Offering statuses cover draft, published, paused and closed; there is no separate prohibited state or policy enforcement in this S3 implementation. Related-word filtering and paging now run in the EF database query; actual SQL translation, indexes and latency remain unverified until the opt-in SQL and workload checks run. No release gate is closed by this report.

The existing opt-in F3 SQL Server acceptance test now also checks S3 search query translation, self/detail visibility and a known location exclusion against a disposable migrated SQL database. Required connection and write opt-in variables were absent on this run, so that test remained skipped. See connecto-api/F3_ACCEPTANCE.md for prerequisites and cleanup behaviour.

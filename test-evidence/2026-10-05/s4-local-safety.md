# S4 local safety and durable-effects implementation

5 October 2026, Pacific/Auckland. Local implementation and tests only; S4 release acceptance is open.

The API persists member blocks and private safety reports. A block is idempotent and excludes both members' offerings from authenticated search, detail and Need matching; unblocking restores normal eligibility. A signed-in member can report another provisioned member without an engagement or completed work, optionally naming an Offering owned by the subject. Own-report reads exclude other reporters. Reports become operator cases; case list, detail and review require a configured Cognito group in `Safety:OperatorGroup`. The default empty setting denies all operator access. Review records the operator subject and time but makes no adjudication or escalation decision.

Safety writes add outbox rows in the same EF `SaveChanges` transaction. A hosted dispatcher projects them into a journey-event ledger and writes a unique consumer receipt. Receipt, projection and delivery marker save together on SQL Server; a replay after a lost acknowledgement cannot add a second projection. The React Offering detail exposes block/report actions; Profile shows own reports, blocked member IDs with unblock, and an operator queue. The API public Offering DTO now includes an internal member ID needed for those safety actions. Report text is never put in a URL or public Offering DTO.

Verification: 41 backend tests passed and one opt-in SQL acceptance test skipped; 48 frontend tests passed; frontend lint and production build passed. New tests cover member isolation, block visibility, group denial/allowance, report privacy, and replay after clearing delivery markers. Backend tests use EF InMemory and synthetic signed JWTs. No real SQL transaction/concurrent dispatcher, migration against a disposable SQL database, Cognito group configuration, authenticated browser, real operator workflow, crash kill/restart, or staging test was performed. The generated EF migration was inspected but not applied. These gates remain open, as do named reviewer, coverage, escalation/appeal and retention decisions for a real-member pilot. No deployment or Git publication occurred.

The EF tool also generated an idempotent SQL script locally without connecting to a database. It contains CREATE TABLE statements for all five S4 tables. This validates script generation only, not execution or migration compatibility against existing data.

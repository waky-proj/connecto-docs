# S5 local connection request implementation

6 October 2026, Pacific/Auckland. This records local code and test results, not S5 release acceptance.

The existing ASP.NET Core API now stores connection requests against a published Need owned by the sender and a published Offering owned by another member. The request holds explicit proposed work terms, NZD price basis and optional amount, both listing revisions, server-derived sender and recipient IDs, a status, a request revision and timestamps. The sender cannot set participant IDs. The API rejects stale or unavailable listings, self requests, mutual blocks, invalid terms and a duplicate pending Need/Offering pair. A filtered unique SQL index protects the pending pair from concurrent inserts when the migration is applied. Only participants can read request detail or the paginated inbox. The recipient can decline and the sender can withdraw a pending request using its current revision; terminal requests remain visible in the inbox. There is no accept or agreement action in S5.

The React Offering detail has a proposal form for signed-in API offerings and the member's published Needs. The API inbox loads server records, supports refresh, shows sent/received and terminal states, and provides role-appropriate decline or withdraw actions with error handling. Demo chat remains session-only and separate.

Verification: 42 backend tests passed, one opt-in SQL acceptance test skipped; 49 frontend tests passed; frontend lint and production build passed. Authenticated API tests use EF InMemory and synthetic signed JWTs. They cover participant permissions, duplicate requests, fresh-client inbox read, decline, withdraw, stale revision and terminal state. The generated `AddConnectionRequests` migration and local idempotent SQL script were inspected for the table and filtered unique pending-pair index. The script was not applied to SQL Server. No real SQL concurrency/restart, Cognito multi-account browser, accessibility, staging or deployment acceptance was performed. S5 release acceptance remains open. S6 acceptance, capacity checks and immutable agreements remain future work.

# S6 LocalDB acceptance and follow-up fixes

7 October 2026, Pacific/Auckland. This updates the earlier local S6 evidence in `2026-10-06/s6-local-acceptance.md`. It is local SQL Server acceptance, not staging or release acceptance.

A dedicated disposable `ConnectoS6Acceptance_20261007` database on SQL Server LocalDB 17 was created and migrated through `AddAgreements` and the concurrently added `AddConversations` migration. The new opt-in SQL acceptance test sent 20 simultaneous accept attempts across two pending requests for one Need. After fixing deadlock handling and locking the Need before request/capacity reads, it passed: exactly one Engagement persisted, the winning request was accepted, the other remained pending, a matching retry returned the same agreement, a competing retry conflicted, and a fresh API host read the saved agreement. The unique NeedId and ConnectionRequestId SQL indexes were created by the migration. The test uses synthetic signed JWTs and cleans up its fixture rows.

An initial SQL run exposed HTTP 500 responses because EF wrapped SQL Server deadlock 1205 errors. Acceptance now takes an exclusive Need row lock before reading request state in a serializable transaction, and maps known SQL deadlock, uniqueness and concurrency failures to HTTP 409. A separate full-suite run exposed a pre-existing listing-update tracking bug in the older F3 SQL test: reattaching skill navigation graphs attempted to reinsert existing Users and Needs. NeedDbService and OfferingDbService now copy scalar skill fields into new child rows. The full backend suite then passed: 46 passed, zero failed and zero skipped, including both opt-in SQL tests. Frontend verification after correcting a stale inbox message and refresh-on-action-error: 51 tests passed, lint and production build passed.

The disposable SQL database is local only. After testing it was dropped, and `DB_ID('ConnectoS6Acceptance_20261007')` returned NULL. No Cognito two-account browser journey, accessibility, staging, deployed SQL migration or capacity/cancellation operating-policy approval was performed. S6 code and local SQL acceptance are complete; release acceptance remains open.

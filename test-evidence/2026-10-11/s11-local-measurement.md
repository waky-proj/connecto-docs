# S11 local cohort measurement implementation and verification

Date: 11 October 2026 (Pacific/Auckland). Source: continuation of the S11 request in this chat. This follows the 9 October partial reporting record; it supersedes its statement that discovery and suitability signals are absent.

## Implemented locally

The existing API host now persists actor-bound `PilotSignal` rows for a published Need's match search and an explicit requester suitability mark. `POST /api/pilot/signals/discovery` recomputes the eligible candidate count on the server; `POST /api/pilot/signals/suitable` requires an owned Need, a prior recorded search, an active other-member Offering, no member block and current inclusion in that Need's eligible match results. Member, kind and client retry key have a unique SQL index. Same-key same-payload retries return the original row; changed payloads conflict. The `AddPilotSignals` migration is additive. The React match flow records a search after a successful match response and exposes a “Mark suitable” action on an API match detail. The browser demo does not call these endpoints.

`GET /api/pilot/metrics` requires the configured safety operator or pilot viewer Cognito group and uses a half-open UTC window of at most 366 days. It reports distinct searched Needs, covered Needs with at least one server-verified eligible candidate, and marked suitable Need–Offering pairs and covered Need denominator. A separate request-created cohort reports request states, acceptance conversion, both-confirmed completion, unilateral reports, cancellation, disputes, eligible review participation, bilateral published review coverage, published requester and provider rating dimensions, median hours to acceptance and repeat participants. Numerators, denominators and definitions are returned to the read-only pilot UI. Outbox replay does not create new requests or agreements, and duplicate signal retry keys do not increase distinct Need or Need–Offering counts. No business success threshold is inferred from ratings.

## Limits and release gates

These checks use synthetic Cognito tokens and a local SQL Server; the React flows were not exercised in a real multi-account browser. Discovery coverage is among Needs with an instrumented search in the selected window, not all published Needs or all pilot members. The report is a live snapshot: later acceptance, outcomes and review publication can change a request-created cohort. Representative pilot enrollment, observation windows, targets and coverage-bias interpretation require the owner's decision. Real configured Cognito group access, staging migration, S3 behavior, accessibility, full browser journey, staging backup restore, runtime database/storage secret rotation, failed-migration rollback and owner review remain unverified. No deployment or release acceptance is claimed. The operational evidence checklist is in the 9 October S11 record.
